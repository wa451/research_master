# 既知の制約

## モデル境界

- ゾーンは論理位置であり、座標、検知扇形、身体姿勢、歩行速度の個人差は持たない。
- 物理部屋・ゾーングラフは無向で、一方通行や時刻依存移動時間は扱わない。
- routineは週間設定で、祝日、季節、病気、来客、学習済み個人モデルはない。
- 分布は設定可能だが、住人別・活動別の階層ベイズ推定やAruba個別系列からの学習はしない。
- 副次活動は1段だけで、割込み中の追加割込みは行わない。
- 同じ住人が同じ共有デバイスを複数の同時活動から重複利用する設定は拒否・回避する。
- 連続環境値、電力、温湿度、音響、Tuya周期report、メーカー固有プロトコルは対象外。

## 現実性

realistic 7日(seed 42)の研究入力は230.9イベント/日で、functional 78.9の2.93倍だが、
Aruba 6,924.4の約3.3%に留まります。Arubaには数秒単位の同一センサー再発火が多い一方、
本実装は因果的な移動・操作だけを出し、無意味な反転や周期発火を追加しません。このため10倍目標
は未達です。

正式ネットワークJSONのOther時間率は72.73%から26.12%へ低下し、30%以下の望ましい目標を
達成しました。ADL内状態変化は136から334（2.46倍）、状態遷移は212から422（1.99倍）で、
各3倍目標は未達です。固定K=15なので設定上の代表状態数は増えませんが、7日内に観測された
非Other代表状態は7から12へ増えました。

研究側のnetwork生成と`evaluate_adl_labels.py`によるstate-series再構築は、同じK/h/1秒/5秒
条件でもOther率が異なります（最終試行でnetwork 26.12%、再構築series 16.59%）。比較表では
既存72.73%と同じnetwork JSON定義を使用し、pipeline診断には両方を記録します。

時間帯Jensen–Shannon距離、イベント間隔Wasserstein距離、ADL継続時間距離、部屋発火順位
JS、遷移確率順位L1はfunctionalより改善しましたが、統計的等価性を意味しません。

## センサー不完全性

不完全性はstress専用の観測変換で、物理的なセンサー回路モデルではありません。safe modeは
同一状態連続を防ぎますが、遅延・欠損後の観測列が在室真値と一致する保証は意図的にありません。
false triggerは設定イベントを起点に生成する簡略モデルです。通常・realisticでは完全に無効です。

## データ利用

- Arubaの主要評価を合成データで置換できない。
- zone→room統合は研究側の列数を抑えるが、複数ゾーンの同時状態情報を失う。
- 多人数の同名ADL境界は既存研究parserがresident IDを真値キーにしないため、ADL性能評価には
  単身realisticを優先する。
- Arubaに在室真値はないため、合成の在室時間とArubaの発火割合を同一指標として比較しない。
- タイムゾーンは固定オフセットで、夏時間規則の長期変化を適用しない。

本実装はHESTIA公式実装、原著設定、Tuya形式と互換ではありません。合成データは機能回帰、
制御された追加評価、耐性評価に限定し、実生活の忠実な再現やArubaの代替と主張しません。
