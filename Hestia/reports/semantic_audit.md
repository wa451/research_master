# HESTIA論文意味論監査

## 監査条件

- 参照資料: リポジトリ内 `references/hestia_paper_v2.pdf`（v2、2025-02-12）
- 方針: 論文と公開要件だけを参照したクリーンルーム監査。原著ソースは参照・複製していない。
- 対象: 設定、住宅トポロジ、住人プロセス、活動、副次活動、デバイス、出力、再現性。
- 判定: `対応`、`独自拡張`、`差異`、`未対応`、`論文から判断不能`。

## 発見した問題と修正

### 1. 活動前デバイス状態の復元

修正前は最後の利用者が終了すると常に`OFF`へ遷移しており、論文の「活動前状態に戻す」意味論と不一致だった。デバイスの最初の利用開始時に主状態と属性を保存し、共有利用者が全員終了した時だけ保存状態へ戻すよう修正した。初期`ON`かつ任意属性、利用者交代、重複利用を回帰テスト化した。

### 2. CASAS/Aruba活動区間互換性

従来`aruba.txt`は全行5フィールドで、研究側のADL parserが必要とする末尾`begin/end`を持たなかった。後方互換の`legacy`は維持し、`motion-door`と`all-devices`プリセットを追加した。新形式はセンサー行を4フィールド、活動境界を6フィールドにし、実研究CLIで1日11区間、7日76区間として解釈できることを確認した。

### 3. 曖昧・不正な設定

- 同一DoorSensorを複数接続に割り当てる設定を拒否する。
- 接続に使うDoorSensorは`CLOSE`で開始する。
- デバイス型に合わない初期状態・活動操作状態を拒否する。
- CASASプリセットが未対応状態を無言で出力せず、明示的に失敗する。

## 自動意味論検証

`validate_generated_events`は構文検査に加えて次を全出力時に検査する。

1. 全部屋キー、住人ID、住人の一意な所在、収容人数。
2. 移動中を挟んだ隣接部屋間移動。非隣接ジャンプを拒否。
3. MotionSensorとその瞬間の部屋在室有無の完全一致。
4. 活動の住人・部屋・ID、主/副活動の入れ子、正の継続時間、許可済み関連活動。
5. 主活動開始列と曜日routineの前方一致。
6. 同一状態・値の連続イベント抑制。
7. DoorSensorのOPEN/CLOSE対応、同一操作住人、設定移動秒数。
8. 利用中デバイスのpriority調停、好み属性、残利用者がいる間の停止禁止。
9. 最終利用終了時の活動前状態復元。
10. 終了時の移動中住人、未終了活動、未終了利用、開いた扉がないこと。

## 境界条件の検証結果

| 条件 | 結果 |
|---|---|
| 同時刻・反対方向の同一ドア通過 | Resourceで直列化、デッドロックなし |
| 容量1の満室への入室 | 退出で容量が空くまで待機し、その後開始 |
| 日付またぎ長時間活動 | horizonで切り詰め、時刻逆行なし |
| 主活動残時間に近い長い副活動 | 残時間以下に制限、正しく入れ子・復帰 |
| 副活動確率0、1、総和/個別1超過 | 0/1は決定的、1超過は設定時拒否 |
| priority同値 | resident ID辞書順で決定 |
| 一人が残る部屋の退出 | MotionSensorはONを維持 |
| 同一機器の共有利用 | 残利用者がいる間はOFFにしない |
| 同時刻順序・入力コレクション順変更 | 完全出力ハッシュ一致 |
| 無効参照、到達不能部屋、曜日欠落 | Pydantic検証で拒否 |
| 空routine | 初期化だけ生成し正常終了 |
| days 0/負値 | 実行前に拒否 |
| 状態重複 | rawは状態+属性、simpleは主状態で抑制 |
| CASASフィルタ・境界有無 | プリセットと明示フラグを検証 |
| 初期ON機器の最終状態 | ONと元属性へ復元 |
| 30日以上 | 30/220日で完走・最終暦日到達 |

## 残る制約

- 実モーションセンサーの反復発火・誤検知・欠測を生成しない。
- routineの時刻変動は活動durationの累積だけで、開始時刻の独立分布や季節性を持たない。
- 部屋移動は最短経路で、意図的な迂回や一時停止をモデル化しない。
- 多人数で同一ADLラベルが完全に重なるCASAS境界は、研究側parserが住人IDを区別しないため、教師区間用途では単身presetを推奨する。
- Tuya互換、周期report、音響機器、電力・環境テレメトリは対象外。
