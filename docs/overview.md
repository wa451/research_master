# この研究は何をするのか

## 一言でいうと

家の中の人感・開閉・家電などのセンサ記録から、繰り返し現れる生活行動の流れを見つける研究です。提案手法は、生の時系列をそのままLLMへ渡す代わりに、まず「家の状態」とその移り変わりをネットワークとして要約し、そのネットワークから行動パターンを抽出します。

例えば、朝に「寝室の人感センサが反応する → 浴室のセンサが反応する → キッチンのセンサが反応する」という流れが繰り返されるなら、起床後の身支度や朝食に関係する候補として扱います。これは行動を確定診断する仕組みではなく、センサ記録に繰り返し現れる候補を見つけ、ラベル付きデータでどの程度意味のある候補かを評価するものです。

## 研究の流れ

```text
センサイベント
  → 同じ時刻の家の状態へそろえる
  → よく現れる状態だけに要約する
  → 状態の移り変わりをネットワーク化する
  → 行動パターン候補を抽出する
  → 既存手法・正解ラベルと比較して評価する
```

処理を構成する段階と入出力は、[パイプライン](architecture/pipeline.md) にあります。

## 最初に知っておく用語

| 用語 | このリポジトリでの意味 |
|---|---|
| センサイベント | ある時刻に、あるセンサが反応したという1件の記録です。 |
| 状態ベクトル | その時刻に各センサがONかOFFかを並べた、家全体の状態です。 |
| 代表状態 | 多数ある状態のうち頻繁に現れる状態を選んだものです。`K` は選ぶ数です。 |
| 状態遷移ネットワーク | 代表状態を点、その間の移り変わりを線として表した図・JSONです。 |
| 行動パターン | 2〜4個の状態が続く短い系列です。人の行動を表す候補であり、確定した行動名ではありません。 |
| ADL | Activities of Daily Living（日常生活動作）。食事・睡眠・入浴など、人が付けた生活行動ラベルです。 |
| ベースライン | 提案手法と比べるための既存・単純な方法です。このリポジトリでは頻度や遷移確率などを使います。 |
| LLM | 言語モデルです。提案手法では、状態遷移ネットワークを説明可能な行動パターン候補へ変換するために使います。 |

## 読む順番

研究内容だけを理解したい場合は、次の順が最短です。

1. このページ
2. [パイプライン](architecture/pipeline.md)
3. [評価一覧](README.md#評価文書)から関心のある評価
4. [論文採用パラメータ](research/paper_parameters.md)と[既知の不一致](research/known_issues.md)

実験を再現・実行する場合は、上記に加えて[再現手順](operations/experiment_reproduction.md)を読み、対象の評価文書へ進みます。LLMを使う手順は費用とAPI呼び出しを伴うため、保存済み成果物と実行条件を確認してから実行してください。

実装を変更する人は、[実装の責務一覧](architecture/code_inventory.md)を入り口にします。ファイル単位の台帳は調査時の参照用で、研究を初めて理解するための文書ではありません。

## 読むときの注意

- 共通設定の既定値と論文で採用した条件は一致しない箇所があります。たとえば代表状態への写像に使うハミング距離の既定値は `h=1`、一部の論文採用条件は `h=0` です。数値を結果として解釈・再現する前に、[論文採用パラメータ](research/paper_parameters.md)と対象評価の条件を確認してください。
- [既知の不一致](research/known_issues.md)は、実装で観測された挙動を研究上の正しい仕様とみなさないための記録です。未解決項目がある評価では、結果の比較・一般化に注意が必要です。
- リポジトリ直下の `ai/` と `AGENTS.md` はコーディングAIが安全に作業するための短い索引・指示です。研究内容の根拠や人向けの説明としては使いません。
